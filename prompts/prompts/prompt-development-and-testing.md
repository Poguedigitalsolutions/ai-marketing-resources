# Prompt Development and Testing Prompt

Use this resource to design, test, review, and improve prompts systematically.

This resource is part of the **Brand Voice AI** methodology developed by **John M. Pogue** and **Pogue Digital Solutions, LLC**.

> A prompt is not magic wording. It is a documented set of instructions, context, boundaries, and completion criteria.

---

## Purpose

This prompt helps transform a vague request into a clear, testable instruction set.

The goal is to define:

- What the AI is being asked to do
- Why the task matters
- What information the AI may use
- What information is missing
- What boundaries apply
- What the output should contain
- What the output should avoid
- How success will be evaluated
- What failure looks like
- Where human review is required
- How prompt versions will be tested and documented

AI can help draft and test instructions.

Humans remain responsible for defining the task, reviewing the output, and approving the final use.

## Core Prompt-Development Principles

A strong prompt should:

- Begin with a clear task
- Define the intended outcome
- Include relevant context
- Identify approved sources
- Separate facts from assumptions
- State important constraints
- Define the audience
- Describe the desired output
- Include completion criteria
- Identify prohibited behavior
- Ask for clarification when necessary
- Include human review
- Be tested with realistic examples
- Be revised based on evidence

A longer prompt is not automatically a better prompt.

A shorter prompt is not automatically a clearer prompt.

The best prompt contains enough information to guide the task without burying the objective under decorative instructions.

## Before You Begin

Gather the information needed to define the task.

Useful inputs may include:

- Business goal
- User goal
- Intended audience
- Source documents
- Brand voice profile
- Customer research
- Offer information
- Examples of successful outputs
- Examples of unacceptable outputs
- Required format
- Required length
- Required platform
- Privacy boundaries
- Compliance requirements
- Approval process
- Existing prompt versions
- Known failure cases
- Test scenarios
- Evaluation criteria

Do not include:

- Passwords
- API keys
- Access tokens
- Private customer records
- Protected health information
- Payment information
- Confidential legal information
- Sensitive employee information
- Proprietary data that has not been approved for use
- Material you are not authorized to provide

## Prompt Anatomy

A practical prompt may contain:

1. Task
2. Purpose
3. Context
4. Audience
5. Source material
6. Role or perspective
7. Constraints
8. Prohibited behavior
9. Process
10. Output structure
11. Completion criteria
12. Review questions
13. Follow-up behavior
14. Human approval requirements

Not every prompt requires every component.

Use only what improves clarity, accuracy, safety, or consistency.

[Paste an existing prompt when revising one.]

Using the supplied information, create a Prompt Development and Testing Report with the following sections:

1. Prompt Summary

State:

- Prompt name
- Primary task
- Purpose
- User
- Audience
- Platform
- Input required
- Output expected
- Main constraint
- Main risk
- Human approver

2. Task Definition

Rewrite the task in plain language.

Include:

- What should happen
- What should not happen
- What information is required
- What decision the output supports
- What action should follow
- What completion looks like

3. Goal Alignment

Separate:

- User goal
- Customer goal
- Business goal
- Communication goal
- Operational goal

Identify any conflicts between them.

Do not optimize a prompt for business convenience when doing so would undermine accuracy, consent, privacy, customer trust, or human judgment.

4. Evidence Review

Organize the provided material into:

- Confirmed facts
- Approved source material
- Brand guidance
- Customer evidence
- Business rules
- Examples
- Assumptions
- Inferences
- Missing information
- Information requiring verification

5. Source Rules

Define whether the AI should:

- Use only supplied sources
- Use supplied sources first
- Use general knowledge
- Conduct current research
- Cite every factual claim
- Distinguish source-derived content
- Avoid unsupported claims
- State when evidence is unavailable

6. Required Inputs

Create an input list containing:

- Input name
- Why it is needed
- Required or optional
- Expected format
- Approved source
- Sensitivity
- Missing-input behavior

7. Missing Information

Identify every missing detail that could materially affect the result.

For each item, include:

- Missing information
- Why it matters
- Risk of proceeding without it
- Best question to ask
- Whether the prompt should stop or continue

8. Clarifying Questions

Create the minimum number of questions required to complete the task accurately.

Order them by importance.

Ask one question at a time when the answers may change the next question.

9. Role Review

Evaluate whether the prompt requires an assigned role.

Possible roles include:

- Editor
- Research assistant
- Interviewer
- Strategist
- Analyst
- Quality reviewer
- Customer journey mapper
- Brand voice assistant
- Workflow designer

Explain:

- Why the role is useful
- What authority the role does not have
- What expertise must not be implied
- Whether the role can be removed without weakening the prompt

10. Context Design

Identify the context necessary for the task.

Include:

- Business context
- Audience context
- Offer context
- Customer context
- Historical context
- Platform context
- Brand context
- Legal or policy context
- Source context
- Approval context

Remove context that does not help the task.

11. Constraint Design

Define constraints for:

- Length
- Tone
- Reading level
- Format
- Platform
- Vocabulary
- Claims
- Sources
- Privacy
- Confidentiality
- Accessibility
- Compliance
- Personalization
- Calls to action
- Human approval

12. Prohibited Behavior

State what the AI must not do.

Possible prohibitions include:

- Invent facts
- Invent quotations
- Invent customer stories
- Invent statistics
- Assume consent
- Reveal confidential information
- Use manipulative urgency
- Imply unsupported expertise
- Make guarantees
- Present assumptions as facts
- Copy a source too closely
- Add unrelated advice
- Publish without approval
- Continue when required information is missing

13. Output Design

Define the required structure.

For each section, include:

- Section name
- Purpose
- Required information
- Optional information
- Length guidance
- Evidence requirement
- Approval requirement

14. Completion Criteria

Create measurable completion criteria.

The prompt is complete when:

- The task has been fulfilled
- Required sections are present
- Sources are handled correctly
- Constraints are followed
- Unsupported claims are removed
- Missing information is disclosed
- Brand voice is preserved
- Privacy boundaries are respected
- The output is usable
- Human review questions are included

15. Draft Prompt

Create a clean prompt using this structure when relevant:

```text
TASK

[State the task clearly.]

PURPOSE

[Explain why it matters.]

CONTEXT

[Provide relevant background.]

AUDIENCE

[Describe the intended audience.]

SOURCE MATERIAL

[Provide approved inputs.]

SOURCE RULES

[Explain how sources may be used.]

BRAND VOICE

[Describe the voice and tone.]

CONSTRAINTS

[List boundaries.]

DO NOT

[List prohibited behavior.]

PROCESS

[Describe the required steps.]

OUTPUT

[Define the structure.]

COMPLETION CRITERIA

[Define when the task is finished.]

HUMAN REVIEW

[List what must be checked.]
```

16. Plain-Language Version

Create a simplified version of the prompt that preserves the important instructions while removing unnecessary wording.

17. Minimum Viable Prompt

Create the shortest version that still contains:

- Task
- Essential context
- Critical constraints
- Output format
- Completion criteria

Explain what was removed and why.

18. Expanded Prompt

Create a more detailed version for complex or higher-risk use.

Add only instructions that improve:

- Accuracy
- Consistency
- Source handling
- Privacy
- Safety
- Quality control
- Human review

19. Instruction Priority

Organize instructions into:

### Critical

Instructions that must always be followed.

### Important

Instructions that materially improve quality.

### Optional

Instructions that may improve the output but are not essential.

Remove instructions that are decorative, repetitive, contradictory, or impossible to evaluate.

20. Conflict Review

Identify conflicts such as:

- Be concise versus include extensive detail
- Use only sources versus add outside knowledge
- Sound conversational versus remain highly formal
- Ask questions versus produce an immediate answer
- Personalize deeply versus minimize data
- Automate execution versus require approval
- Be persuasive versus avoid pressure

Recommend how each conflict should be resolved.

21. Ambiguity Review

Identify wording that could be interpreted in multiple ways.

For every ambiguous instruction, provide:

- Original wording
- Possible interpretations
- Risk
- Recommended wording

22. Redundancy Review

Identify repeated instructions.

Recommend whether to:

- Keep one version
- Combine them
- Move them into a checklist
- Remove them

23. Feasibility Review

Identify instructions the AI may not be able to complete reliably.

Examples include:

- Accessing unavailable systems
- Confirming private facts
- Verifying information without sources
- Guaranteeing outcomes
- Making regulated decisions
- Approving legal compliance
- Publishing to an external platform without integration
- Remembering information permanently without a supported memory system

Rewrite the prompt so it does not promise unsupported capabilities.

24. Failure-Mode Analysis

Identify likely failures such as:

- Hallucinated facts
- Unsupported claims
- Generic language
- Loss of brand voice
- Excessive length
- Missing sections
- Weak reasoning
- Unclear calls to action
- Repetition
- Overconfidence
- Privacy violations
- Source confusion
- Incorrect assumptions
- Failure to ask questions
- Ignoring platform requirements

For each failure, include:

- Cause
- Warning sign
- Prevention instruction
- Test case
- Human review step

25. Test Plan

Create a test plan containing:

- Test ID
- Scenario
- Input
- Expected behavior
- Expected output
- Failure condition
- Reviewer
- Result
- Revision needed

26. Representative Test Cases

Create test cases for:

- Complete information
- Missing information
- Conflicting information
- Ambiguous instructions
- Sensitive information
- Unsupported factual claim
- Weak source material
- Strong source material
- Short input
- Long input
- Off-topic input
- User correction
- Audience change
- Platform change
- Brand voice conflict

27. Edge Cases

Test how the prompt handles:

- No source material
- Incorrect source material
- Outdated source material
- Private information
- A request outside the prompt’s scope
- A request requiring professional advice
- Conflicting customer and business goals
- An impossible deadline
- An unsupported guarantee
- A request to skip human review
- A request to imitate a living person too closely
- A request to invent evidence

28. Adversarial Tests

Test whether the prompt resists instructions to:

- Ignore source rules
- Reveal confidential information
- Invent statistics
- Bypass approval
- Make false claims
- Use prohibited language
- Exceed the requested scope
- Pretend certainty
- Override consent
- Publish unreviewed material

29. Brand Voice Tests

Evaluate whether the prompt preserves:

- Vocabulary
- Sentence rhythm
- Tone
- Warmth
- Authority
- Storytelling
- Signature phrases
- Humor
- Audience respect
- Platform fit

Compare the output with approved examples.

30. Source-Grounding Tests

Check whether the output:

- Uses supplied information accurately
- Distinguishes facts from interpretation
- Identifies unsupported points
- Avoids fabricated citations
- Uses current research when required
- Provides citations when requested
- States when evidence is missing

31. Privacy Tests

Confirm the prompt does not encourage the user to provide:

- Passwords
- Credentials
- Private customer records
- Sensitive personal data
- Payment information
- Protected health information
- Confidential legal information
- Restricted company data

32. Accessibility Tests

Evaluate:

- Reading level
- Heading structure
- Link descriptions
- Alternative text guidance
- Plain language
- Sentence length
- Instructions for visual material
- Mobile readability
- Keyboard-friendly formats
- Accommodation needs

33. Output Evaluation Rubric

Score each output from 1 to 5 for:

- Task completion
- Accuracy
- Source use
- Clarity
- Relevance
- Structure
- Brand voice
- Audience fit
- Constraint compliance
- Privacy
- Accessibility
- Usability
- Human-review readiness

Define what each score means.

34. Pass and Fail Criteria

Define:

### Pass

The output completes the task, follows critical instructions, handles sources correctly, respects constraints, and is ready for human review.

### Conditional Pass

The output is usable but requires identified corrections.

### Fail

The output contains significant factual, structural, privacy, source, brand, or instruction-following problems.

35. Prompt Comparison

When comparing prompt versions, evaluate:

- Accuracy
- Consistency
- Length
- Clarity
- Completion rate
- Source handling
- Hallucination rate
- Brand alignment
- Review time
- User effort
- Failure frequency

Do not select a version based only on which output sounds more polished.

36. A/B Test Plan

Create a controlled comparison between two prompt versions.

Keep consistent:

- Task
- Inputs
- Model
- Settings
- Test cases
- Reviewer
- Scoring rubric

Change only the prompt instructions being tested.

37. Revision Recommendations

For every recommended change, include:

- Current wording
- Problem
- Evidence
- Revised wording
- Expected improvement
- Risk
- Test required

38. Prompt Version Record

Create a version table containing:

- Version number
- Date
- Author
- Change
- Reason
- Test result
- Approver
- Status
- Next review date

39. Prompt Naming Convention

Recommend a naming structure such as:

```text
[Category] - [Task] - [Audience or Channel] - v[Version]
```

Example:

```text
Content - LinkedIn Article Development - Founders - v1.2
```

40. Prompt Library Metadata

For each prompt, document:

- Prompt name
- Category
- Owner
- Purpose
- Audience
- Required inputs
- Approved sources
- Risk level
- Human approval
- Current version
- Last tested
- Next review
- Related resources
- Archived versions

41. Risk Classification

Classify the prompt as:

### Low Risk

Brainstorming, formatting, summarizing approved material, or internal ideation.

### Moderate Risk

Customer-facing drafting, personalization, research summaries, marketing claims, or workflow recommendations.

### High Risk

Sensitive data, regulated topics, major financial decisions, legal matters, medical matters, security, automated publication, or high-impact customer decisions.

Explain the classification.

42. Human Approval Checkpoints

Require human review before:

- Publishing externally
- Sending customer communication
- Making factual claims
- Using customer stories
- Using testimonials
- Presenting statistics
- Naming individuals
- Sharing sensitive information
- Making legal, medical, or financial recommendations
- Activating an automation
- Updating an official knowledge base
- Replacing an approved prompt version

43. Prompt Maintenance Plan

Define:

- Owner
- Review frequency
- Testing frequency
- Trigger for revision
- Source update process
- Versioning process
- Approval process
- Archive process
- Incident-review process

44. Incident Review

When a prompt produces a harmful or unusable result, document:

- Date
- Prompt version
- Input
- Output
- Failure
- Customer or business impact
- Immediate correction
- Root cause
- Prompt revision
- Test added
- Approver
- Resolution

45. Final Prompt Package

Finish with:

- Prompt name
- Purpose
- Intended user
- Intended audience
- Risk level
- Required inputs
- Source rules
- Critical constraints
- Final prompt
- Test cases
- Evaluation rubric
- Pass criteria
- Human approval requirements
- Version
- Owner
- Next review date

46. Human Review Questions

Finish by asking:

- Is the task clear?
- Is the desired outcome clear?
- Is the audience defined?
- Are approved sources identified?
- Are facts separated from assumptions?
- Is missing information acknowledged?
- Are the constraints necessary?
- Are prohibited behaviors explicit?
- Is the output structure usable?
- Are completion criteria measurable?
- Are privacy boundaries clear?
- Does the prompt preserve the brand voice?
- Have realistic test cases been used?
- Have edge cases been tested?
- Are failure modes documented?
- Is human approval required at the right points?
- Is the current version documented?
- Would another person know how to use and evaluate this prompt?
```

## Recommended Follow-Up Prompts

### Follow-Up 1: Simplify the Prompt

```text
Review this prompt and remove decorative, repetitive, vague, or unnecessary instructions. Preserve every instruction required for accuracy, source handling, privacy, brand voice, output quality, and human review.
```

### Follow-Up 2: Find Hidden Assumptions

```text
Identify every assumption in this prompt about the user, audience, business, customer, platform, sources, tools, permissions, or desired outcome.
```

### Follow-Up 3: Create Test Cases

```text
Create realistic test cases for complete information, missing information, conflicting information, weak sources, sensitive data, off-topic requests, and attempts to bypass the prompt’s rules.
```

### Follow-Up 4: Compare Two Versions

```text
Compare these two prompt versions using the same inputs, test cases, scoring rubric, and reviewer criteria. Identify which instructions caused meaningful differences.
```

### Follow-Up 5: Audit Source Grounding

```text
Review the prompt for source-handling weaknesses. Add instructions that prevent unsupported facts, fabricated citations, silent assumptions, and confusion between supplied content and outside knowledge.
```

### Follow-Up 6: Audit Privacy and Risk

```text
Review the prompt for privacy, confidentiality, security, consent, compliance, and human-approval risks. Recommend specific safeguards.
```

### Follow-Up 7: Create the Prompt Library Record

```text
Create a complete prompt-library entry containing the prompt name, owner, purpose, audience, required inputs, source rules, constraints, risk level, test history, current version, approval status, and next review date.
```

- Are approved sources identified?
- Are missing inputs handled?
- Are assumptions visible?
- Are constraints useful?
- Are conflicting instructions resolved?
- Are prohibited behaviors explicit?
- Is the output structure defined?
- Are completion criteria measurable?
- Are privacy boundaries included?
- Are source rules included?
- Are brand voice requirements included?
- Are failure modes documented?

## Important Principle

A prompt should not depend on lucky wording.

It should make the task, evidence, boundaries, and definition of success visible enough that another person can test it, improve it, and trust how it is being used.
